### Паттерны проектирования
Паттерны проектирования используются при разработке архитектуры программы.  
Они помогают применять уже выробаттые и проверенные концепции для реализации задач.  
Так же патерны стандартизируют процесс разработки.   
Существует 22 классических паттерна проектирования и они делятся на три группы:  
- Порождающие применяются для гибкого создания объектов без внесения в код лишних зависимостей
- Структурные показывают различные способы построения связей между обхектами
- Поведенческие описывают эффективную коммуникацию между объектами

### @Builder
Паттерн присутствующий в Lombok. Билдер - паттерн проктирования, применяемый для удобного построения сложного объекта.  
Используется к примеру при работе с классом StringBuilder, когда после вызова методов append() создается строка.  
Имеет преймущества:  
- можно создавать обхекты поэтапно
- можно использовать один и тот же код для создания различных тепом объектов
- код сборки объекта изолируется от основной логики программы

### @Value
инструмент для создания неизменяемых (immutable) классов с минимальным количеством кода.  
Она является «неизменяемым» аналогом более известной аннотации @Data  
@Value автоматически генерирует код для класса, который должен представлять собой неизменяемую сущность.  
В отличие от @Data, она не генерирует сеттеры (setters), что делает объект  
потокобезопасным и предсказуемым после создания 

При применении к классу, эта аннотация выполняет следующее:
- Поля: Все поля по умолчанию становятся private и final.
- Класс: Сам класс помечается как final, чтобы от него нельзя было унаследоваться и нарушить неизменяемость.
- Методы: Генерируются геттеры (getters) для всех полей, а также методы toString(), equals() и hashCode().
- Конструктор: Генерируется конструктор, принимающий все аргументы (all-args constructor).

Если вы используете одновременно @Value и @Builder, конструктор, созданный для билдера,  
будет иметь приоритет над тем, который хотел создать @Value.

Чтобы не строить объект заново, можно скопировать существуюший. Для этого нужно добавить   
преобразование готового неизменяемого объекта в билдер с помощью аннотации @Builder(toBuilder = true)

Метод toBuild() вернет билдер с уже проинициализированным на основе исходного объекта полями.   
После этого в них можно поменять какое либо значение и сконструировать нужный объект.
